# MiMoCode Guard 1.3 — Data Expansion Plan

## Decision

Keep the original Candidate A implementation as the primary baseline. Candidate B remains a controlled comparison. TinyBrainBot is excluded. This branch does not change model architecture or claim deployment readiness.

## Why data work comes first

The 1.2 diagnostics report 105,207 training rows, 17,235 validation rows, and 14,055 test rows. The label mix differs materially: Critical is 20.13% in train, 38.89% in validation, and 28.00% in test. The report also identifies recurring Critical false-safe tokens including `wipefs`, `mkfs.ext4`, `flashrom`, device paths, and wrapper tokens such as `sudo` and `nohup`.

The 1.2 validation report records Critical recall 0.9758, Safe FPR 0.0084, non-critical FPR 0.1998, and High+Critical recall 0.9555. These are not deployment pass results.

## Expansion policy

1. Keep the original v1.5 dataset and its existing split frozen as the reproducible baseline.
2. Add independently sourced examples with explicit provenance. Prefer real-world command corpora and audited references; every new risk label must receive human review. Do not treat model-generated labels as ground truth.
3. Every supplemental record must carry `command`, `shell`, `label`, `family_id`, `source`, and `reviewed: true`. A `family_id` may legitimately contain multiple labels when different parameterizations change the impact; never force one label across the whole family. Keep the full family in one split.
4. Supplemental rows are training-only. Never append new samples to validation/test to make metrics look better.
5. Group command templates and close variants by `family_id` before any new split is made. A family must never cross train/validation/test.
6. Include hard Safe examples that resemble dangerous commands, plus parameter/path/wrapper variants of reviewed risky examples. Preserve labels only when the semantics are unchanged and a reviewer confirms them.
7. Remove secrets and credentials. Treat commands as inert text; never execute them.
8. Deduplicate normalized commands and audit label consistency by family.
9. Compare Candidate A baseline vs Candidate A expanded-data run on the same frozen validation/test protocol. Thresholds are selected on validation only; test remains report-only.
10. Do not relax deterministic policy controls. A model prediction of Safe is never authorization to execute a command.

## Validate a reviewed supplement

Prepare UTF-8 JSONL with one reviewed record per line. Required fields are `command`, `shell`, `risk_level`, `risk_categories`, `reversible`, `requires_root`, `explanation`, `safer_alternative`, `source`, `provenance`, `derived_from`, `family_id`, and `reviewed: true`. Labels must follow the upstream taxonomy. Family IDs must be `hybrid:<derived_from>`, `generated:<seed-id>`, or `open_source:<sha256 of normalized command>`. Then run:

```bash
python tools/validate_v13_supplement.py --input reviewed_supplement.jsonl
```

The validator writes `v13_supplement_train.jsonl` and a SHA-256 manifest. It rejects incomplete schema, unreviewed rows, duplicate normalized commands per shell, invalid family identifiers, inconsistent safe-category metadata, and likely credential material. It reports the source hash and label counts. Different labels within a family are allowed; keep the full family in one split.

## Important integration boundary

The current pinned trainer consumes the upstream `yannelli/cli-command-risk` dataset at revision `v1.5`. This branch first establishes a strict supplemental-data intake and audit contract. The supplement must not be represented as training input until the trainer's dataset loader explicitly consumes it and records its hash in the run manifest. Do not silently change the source dataset or split.

## Acceptance gates

- Candidate A remains the primary model.
- Package size <= 10 MiB and CPU-first.
- Validation Critical recall >= 0.99, High+Critical recall >= 0.97, Safe FPR <= 0.05, non-critical FPR <= 0.20; report all metrics, not just pass/fail.
- Also report per-command-family recall, confusion matrix, calibration, latency, and package size.
- Test metrics are report-only. If a gate fails, remain Research Only.


## Source-quality note

The upstream dataset card describes 136,497 rows from 1,258 template families and says the labels were model-authored and not individually human-reviewed. Its rows are highly templated variants. Therefore, simply generating more parameter combinations from the same templates is not meaningful independent data expansion. Prioritize new command families and source-backed examples, and retain reviewer decisions and provenance.


## Build a train-only DatasetDict

After validation, run:

```bash
python tools/prepare_v13_dataset.py --supplement v13_supplement_train.jsonl --revision v1.5 --output /kaggle/working/mimocode_guard_v13_dataset
```

This copies the pinned upstream validation/test splits unchanged and appends reviewed rows only to train. It refuses supplement family or exact command overlap with validation/test and writes a manifest. The current trainer launcher does not yet load this prepared DatasetDict; trainer-loader integration remains a separate required step. Do not describe this as a completed expanded-data training run.
